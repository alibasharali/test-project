## TanStack Start

_Updated 2026-10-21 (TanStack Start 1.x, React 19)._

- `src/routeTree.gen.ts` is generated by the dev server or the build; don't edit it.
- Server-only code (database, secrets, `cloudflare:workers`) runs in server functions or server routes. Never export a server-only helper from a module the client imports: the client bundle pulls in its imports and the build breaks.
- Format dates and times with a component that renders the same on server and client; server and browser time zones differ, and raw `toLocaleString()` breaks hydration.
- Keep logic in plain modules under `src/lib/` so it can be unit-tested without the framework.
- Localized URLs: put page routes under an optional path param (`src/routes/{-$locale}/`), leave the default locale unprefixed, and have that layout route 301 the default-locale prefix and 404 unknown prefixes. Type every other locale's content as `typeof en` so a missing key fails typecheck. When you derive the unprefixed path (hreflang alternates, language switcher), strip only a real locale prefix: a pattern like `/^\/[a-z]{2}/` also eats two-letter routes such as `/cv`.
- Reveal-on-scroll or fade-in content hides only under a class (e.g. `html.js`) that an inline script in the root route's head sets, so SSR'd content is never stuck invisible without JavaScript; honour `prefers-reduced-motion`.
- Page transitions: set the router's `defaultViewTransition: { types }` with a rule that returns `['page']` only when the pathname changes (`false` for search- or hash-only changes, so filters and polling don't animate), give persistent chrome such as a sticky header its own `view-transition-name`, and switch the `::view-transition-*` animations off under `prefers-reduced-motion: reduce`.

## Cloudflare D1

_Updated 2026-10-13._

- One database per environment (`<id>` and `<id>-dev`); the binding (`DB`) is declared in every wrangler environment.
- Schema changes go through Drizzle: edit the schema, `npm run db:generate`, commit the SQL migration. The deploy applies migrations **before** deploying code, since new code may read new columns. Never edit an applied migration.
- When drizzle-kit asks an interactive question (renames), split the change into two migrations instead: sessions can't answer prompts.
- Remote D1 is written by deploys only; local development uses miniflare's local copy (`npm run db:migrate:local`).
- D1 binds at most 100 parameters per query, and local SQLite doesn't enforce it. Filter child rows through a join or subquery on the parent key (`innerJoin(items, …).where(eq(items.projectId, id))`), never `inArray` over an id list that grows with the data.

## Cloudflare Workers

_Updated 2026-10-23 (wrangler 4)._

- **Never deploy by hand.** GitHub Actions deploys per the project's delivery preset: `develop` to the dev Worker and `main` to prod with `environment: dev` / `prod` on the job, or, in Straight to prod, only `main` to prod with `environment: prod`. A PR never triggers a deploy job or records a deployment; the `check` job covers PRs. Verify changes with tests, typecheck, build and the local dev server instead.
- `wrangler.jsonc` environments **don't inherit** bindings, vars or routes: every environment redeclares them. Add a binding to each environment, or it is missing in that one.
- `worker-configuration.d.ts` is generated (`wrangler types`) and not committed; generate it before typechecking a fresh checkout.
- Free plan limits are per request: **50 subrequests** (every `fetch`, including API calls) and 10 ms CPU. Loops that call an API per item fail in production long before they fail in tests; batch, or use list endpoints.
- The Cache API (`caches.default`) has no effect on `*.workers.dev`: `put` and `match` silently do nothing until the Worker serves from a custom domain. To cache an upstream API on workers.dev, use KV or a module-level in-memory copy, or ask for a custom domain; settle it in the spec.
- Secrets come from `wrangler secret put` (runtime) or GitHub Actions secrets (deploys). Never in `wrangler.jsonc` or a committed `.dev.vars`.

## Tailwind CSS v4

_Updated 2026-10-15._

- Configuration is CSS-first: colours and fonts are `@theme` tokens in the stylesheet, not a `tailwind.config.js`. Use the tokens instead of raw colours, and give each a dark-mode value.
- Every page fits a 320px-wide screen with no sideways page scroll: one element wider than the viewport makes phones zoom the whole page out. Check `document.documentElement.scrollWidth` at 320px after any layout change, including headers that gain a button.
- Give a responsive grid an explicit column at every width (`grid-cols-1 sm:grid-cols-2`, not `grid sm:grid-cols-2`), and `min-w-0` on flex and grid children that hold `truncate` text: an implicit column or a child's default `min-width: auto` grows to the full untruncated text.
- Wide content scrolls inside its own box (`overflow-x-auto`), and that box is `relative`, so absolutely positioned children such as `sr-only` labels stay inside it instead of widening the page.

## TanStack Start on Cloudflare Workers

_Updated 2026-10-23._

- Scaffold with the official CLI's Cloudflare target: `npx @tanstack/cli create --framework React --deployment cloudflare --add-ons shadcn --no-examples --no-toolchain` (cli 0.72). It adds no test runner: add vitest yourself. It also imports Google Fonts and devtools; drop them where the site must make no third-party requests.
- Vitest needs its own `vitest.config.ts`: the Cloudflare Vite plugin breaks vitest when it loads `vite.config.ts`.
- Code importing `cloudflare:workers` can't be unit-tested that way, so keep logic in pure modules and routes thin.
- Let the Vite plugin write `src/routeTree.gen.ts` (dev server or build), and keep the standalone `tsr generate` out of scripts: its output differs (no `Register` block), so a typecheck that runs it leaves a diff or breaks server-route types. Either commit the plugin's file or gitignore it and build before `tsc --noEmit`.
- `CLOUDFLARE_ENV` selects the wrangler environment at **build** time (the Vite plugin), and the build redirects wrangler to its output config (`dist/server/wrangler.json`): later commands need no `--env`, and `wrangler deploy` only works after a build.
- Vite's production build drops dotfiles (`.github/`, `.claude/`) from `import.meta.glob` while vitest keeps them; bundle such directories another way.
- Streaming SSR injects inline hydration scripts, so an enforced Content-Security-Policy needs `'unsafe-inline'` in `script-src` (or per-request nonces, which need framework support). Set security headers in the Worker's server entry.

## Free tiers

Never move to a paid plan or create paid resources without asking the developer.

- **Cloudflare D1:** Free plan: 5 million rows read and 100,000 written a day, 5 GB storage. Over a limit, queries fail.
- **Cloudflare Workers:** Free plan: 100,000 requests a day, 10 ms CPU and 50 subrequests per request. Over a limit, requests fail; nothing is billed unless you upgrade.
