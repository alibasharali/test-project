## TanStack Start

_Updated 2026-10-11 (TanStack Start 1.x, React 19)._

- `src/routeTree.gen.ts` is generated by the dev server or the build; don't edit it.
- Server-only code (database, secrets, `cloudflare:workers`) runs in server functions or server routes. Never export a server-only helper from a module the client imports: the client bundle pulls in its imports and the build breaks.
- Format dates and times with a component that renders the same on server and client; server and browser time zones differ, and raw `toLocaleString()` breaks hydration.
- Keep logic in plain modules under `src/lib/` so it can be unit-tested without the framework.

## Cloudflare D1

_Updated 2026-10-11._

- One database per environment (`<id>` and `<id>-dev`); the binding (`DB`) is declared in every wrangler environment.
- Schema changes go through Drizzle: edit the schema, `npm run db:generate`, commit the SQL migration. The deploy applies migrations **before** deploying code, since new code may read new columns. Never edit an applied migration.
- When drizzle-kit asks an interactive question (renames), split the change into two migrations instead: sessions can't answer prompts.
- Remote D1 is written by deploys only; local development uses miniflare's local copy (`npm run db:migrate:local`).

## Cloudflare Workers

_Updated 2026-10-11 (wrangler 4)._

- **Never deploy by hand.** GitHub Actions deploys `develop` to the dev Worker and `main` to prod, with `environment: dev` / `prod` on the job. Verify changes with tests, typecheck, build and the local dev server instead.
- `wrangler.jsonc` environments **don't inherit** bindings, vars or routes: every environment redeclares them. Add a binding to each environment, or it is missing in that one.
- `worker-configuration.d.ts` is generated (`wrangler types`) and not committed; generate it before typechecking a fresh checkout.
- Free plan limits are per request: **50 subrequests** (every `fetch`, including API calls) and 10 ms CPU. Loops that call an API per item fail in production long before they fail in tests; batch, or use list endpoints.
- Secrets come from `wrangler secret put` (runtime) or GitHub Actions secrets (deploys). Never in `wrangler.jsonc` or a committed `.dev.vars`.

## Tailwind CSS v4

_Updated 2026-10-11._

- Configuration is CSS-first: colours and fonts are `@theme` tokens in the stylesheet, not a `tailwind.config.js`. Use the tokens instead of raw colours, and give each a dark-mode value.

## TanStack Start on Cloudflare Workers

_Updated 2026-10-11._

- Vitest needs its own `vitest.config.ts`: the Cloudflare Vite plugin breaks vitest when it loads `vite.config.ts`.
- Code importing `cloudflare:workers` can't be unit-tested that way, so keep logic in pure modules and routes thin.
- `CLOUDFLARE_ENV` selects the wrangler environment at **build** time (the Vite plugin), and the build redirects wrangler to its output config: later commands need no `--env`.
- Vite's production build drops dotfiles (`.github/`, `.claude/`) from `import.meta.glob` while vitest keeps them; bundle such directories another way.
- Streaming SSR injects inline hydration scripts, so an enforced Content-Security-Policy needs `'unsafe-inline'` in `script-src` (or per-request nonces, which need framework support). Set security headers in the Worker's server entry.

## Free tiers

Never move to a paid plan or create paid resources without asking the developer.

- **Cloudflare D1:** Free plan: 5 million rows read and 100,000 written a day, 5 GB storage. Over a limit, queries fail.
- **Cloudflare Workers:** Free plan: 100,000 requests a day, 10 ms CPU and 50 subrequests per request. Over a limit, requests fail; nothing is billed unless you upgrade.
